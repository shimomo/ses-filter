# SES フィルターの仕組み

拡張機能の作りと、精度の測り方をまとめます。使い方は [README](../README.md) にあります。

開発は非公開のリポジトリで進めていて、このリポジトリのコードはそこから書き出したものです。コードのコメントにある「仕様 5.1」「段階2b 仕様 4.3」のような節番号は、公開していない開発文書のものです。

## 全体の構成

拡張機能は、サイトごとのコンテンツスクリプトとポップアップでできています。バックグラウンドの処理はありません。

| 場所 | 役割 |
|---|---|
| `entrypoints/paiza.content.ts`、`green.content.ts`、`doda.content.ts`、`mynavi.content.ts` | サイトごとの入口。対象のページで判定を動かす |
| `entrypoints/popup/` | ポップアップ（設定と、開いているページの集計） |
| `src/sites/` | サイトごとの読み取り（アダプタ）。カードを見つけ、求人ID・企業・各欄の文字を取り出す |
| `src/core/rules.ts` | 言い回しのルール |
| `src/core/classify.ts` | ルールを当て、否定や別の意味を除く |
| `src/core/decide.ts` | 判定の優先順位 |
| `src/core/runtime.ts` | ページを見張り、カードを判定して表示に反映する |
| `src/core/fetchQueue.ts` | 詳細ページの先読み（paiza、マイナビ転職） |
| `src/core/store.ts` | 設定と記録の保存 |
| `src/core/ui.ts` | カードのバーと、画面右下の件数表示 |
| `src/core/normalize.ts` | 社名と文字の正規化 |
| `eval/` | 精度を測る仕組み |
| `assets/icon.svg`、`icon-16.svg` | アイコンの元の絵（ふるいの上に求人票が残る。16px 用は網目と粒を省いたもの）。`pnpm icons` で `public/icon/` の PNG に書き出す |

## サイトごとの読み取り

| サイト | カードから読むもの | ほかに読むもの |
|---|---|---|
| paiza転職 | タイトル、企業名、カードの本文（同じ企業のほかの求人の欄は除く） | 求人の詳細ページ（開発内容タイプ、雇用関係、勤務地、勤務時間、求人概要、職務内容、会社の説明） |
| Green | タイトル、企業名、勤務地、事業内容、カードの本文 | なし |
| doda | タイトル、企業名、勤務地、事業、カードの本文（サイトが付けるキーワードの欄は除く） | なし |
| マイナビ転職（IT エンジニア職の検索結果） | タイトル、企業名、勤務地、カードの本文（サイトが付ける関連キーワードの欄は除く） | 求人の詳細ページ（事業内容、勤務地、勤務時間、雇用形態、本文の区画。広告型の詳細ページは読まない） |

企業は、paiza・Green・マイナビ転職ではサイトの企業ID（マイナビ転職は求人 URL の最初の数字）、doda では正規化した社名で見分けます。社名の正規化では、全角と半角をそろえ（NFKC）、空白と、社名に添えた括弧書きを除き、「（株）」「㈱」を「株式会社」にそろえます。

## ルール

ルールは `src/core/rules.ts` にあり、NFKC で正規化した文字に正規表現で当てます。当てる欄を限るルールもあります（「プロジェクト先」は勤務地だけ、単独の「SES」は事業内容だけ、など）。

- **強いルール**（当たれば畳む）: 客先常駐、客先での勤務、プロジェクト先、勤務地が案件しだいの書き方、帰社日、案件選択、還元率、自社で働く割合が100％未満、SES事業、勤務時間が客先に準ずる、派遣事業、雇用形態が派遣、派遣先
- **中くらいのルール**（要確認の印だけ）: タイトルの「参画」「案件」、商流（エンド直、一次請け、プライム案件など）、待機、「高還元」だけの書き方、派遣の許可番号

次の場合は、ルールに当たっても数えません。

- **否定**: 当たった言葉のすぐあとに「なし」「ありません」「一切」「しません」などが続く場合。「は」「が」「も」をはさむ形や、「・」「、」「／」でつないだ短い1語をはさむ形（「客先常駐・SESなし」）も含みます。
- **別の意味**: 「脱SES」「非SES」「元SES」、「SESを卒業」「SES経験者」「SES出身」「SES歓迎」、「〜から脱却」「〜から転職」、「SES企業とは異なり」「SESではなく」。応募する人の経歴として並べた「SIer・SES・事業会社」も除きます。
- **Amazon SES**: 「SES」の直前10文字以内に「Amazon」か「AWS」があれば、メールのサービスとみなします。
- **消費者向けの還元率**: 「ポイントの還元率」「キャッシュレス決済」のような、利用者への還元の話。

## 判定の優先順位

カードごとに上から順に見て、最初に決まったものを使います（`src/core/decide.ts`）。

1. 利用者が「SESではない」とした求人・企業 → 表示する
2. 利用者が「この企業を常に隠す」とした企業 → 隠す
3. 求人の記録（詳細ページの結果）が「隠す」 → 隠す
4. 企業単位の判定で対象の企業 → 隠す
5. 求人の記録が「要確認」か「何もしない」 → それに従う
6. カードの文字が強いルールに当たる → 隠す
7. 詳細ページのあるサイト（paiza、マイナビ転職）で、先読みがオンで、その求人の記録がまだない → 判定中（詳細ページを読む）
8. カードの文字が中くらいのルールだけに当たる → 要確認
9. それ以外 → 何もしない

paiza の詳細ページは、開発内容タイプに「受託開発（社外常駐）」があれば SES、雇用関係に「派遣」があれば派遣として隠します。どちらもなければ、詳細の各欄にルールを当てます（中くらいのルールだけなら、開発内容タイプが自社内なので何もしない）。開発内容タイプが読めなければ「不明」とし、企業単位の判定とカードの文字で判定します。

マイナビ転職の詳細ページにはサイト自身の分類がないので、雇用形態に「派遣」があれば派遣として隠し、なければ詳細の各欄（事業内容、勤務地、勤務時間、本文の区画）にルールを当てます。中くらいのルールだけなら要確認のままです（サイトの分類で打ち消せないため）。ページ下部のおすすめ求人は他社の求人なので読みません。

## 企業単位の判定

自社内の開発と社外常駐の両方がある企業は、どの求人も対象とします。エンジニアから見ると、SES になる可能性のある企業という時点で避けたいためです。

- 事業内容の欄（Green の事業内容、doda の事業）で強いルールに当たった企業は、「SES企業」か「派遣企業」として記録します。
- そのほかの欄で強いルールに当たった求人と、paiza の詳細ページで隠した求人（会社の説明で当たったものを含む）は、その企業の「対象の求人」として記録します。対象の求人が1件でもある企業は、ほかの求人も隠します（理由は「同じ企業の求人が対象」）。
- 求人自身の記録は、その求人の企業単位の判定には数えません。利用者が「SESではない」とした求人も数えません。カードの文字が変わって当たらなくなった求人は、記録から外します。

## 詳細ページの先読み（paiza、マイナビ転職）

先読みは既定ではオフです。ビルドした人が知らないうちにサイトへ取りに行かないようにするためです。ポップアップでオンにすると、判定中のカードの詳細ページを、ページ上の並び順に読みます。

| 項目 | 値 |
|---|---|
| 同時に読む数 | 1（1件ずつ順番に） |
| 間隔 | 1秒 |
| 1回のページ表示で読む上限 | 30件 |
| タイムアウト | 10秒 |
| 再試行 | 1回（3秒後） |
| 止める条件 | 失敗が3回続いたら、そのタブでは止める |
| 結果を覚える期間 | 30日（「不明」は1日） |

利用者が自分で開いた詳細ページは、通信せずにその場で読み取り、同じように記録します。マイナビ転職の広告型の詳細ページ（URL 末尾が `adv1/`）は、事業内容も本文もないので読みません。読むと「何もしない」が記録され、カードの文字で隠れていた求人が表示に戻ってしまうためです。先読みの URL も `adv1/` なしの形にします。

## 表示と操作

- カードには `data-ses-filter` 属性で状態を付け、サイトの要素は消さずに見た目だけを変えます。状態は、畳む（`collapsed`）、消す（`hidden`）、薄く（`dimmed`）、要確認（`flagged`）、判定中（`pending`）、一時的に表示（`revealed`）、利用者の指定で表示（`allowed`）、何もしない（`plain`）です。
- バーには、理由の上位2件と「ほかN件」を出します。ボタンは「表示」「SESではない」「この企業を常に隠す」です。何もしないカードには「この企業を隠す」、利用者が隠した企業には「隠すのをやめる」、指定で表示しているカードには「取り消す」を出します。
- 画面右下に、隠した・要確認・判定中の件数と、カードを読めないときの警告を出します。
- 失敗したとき（読めないカード、保存の失敗、先読みの停止）は、カードを隠さずに表示したままにします。誤って隠すより、隠しそこねるほうを選びます。

## 保存するデータ

すべて `chrome.storage.local` に保存し、外には送りません。

| キー | 内容 |
|---|---|
| `settings` | 有効・無効、表示の仕方、サイトごとのオン・オフ、詳細ページの先読み、先読みの間隔 |
| `userLists` | 利用者が隠した企業と、「SESではない」とした企業・求人 |
| `job:<サイト>:<求人ID>` | 求人の記録（paiza の詳細ページの結果） |
| `company:<サイト>:<企業>` | 企業の記録（事業内容の当たり、対象の求人、対象外の求人） |

ポップアップの「保存済みの判定を消去」は、求人と企業の記録を消します。利用者の指定は残します。

## 精度の測り方

拡張機能のコード（サイトごとの読み取り、ルール、優先順位、記録の作り方）をそのまま使い、保存した検索結果のページで判定して、正解ラベルと比べます（`eval/`）。

1. **ページを保存する**: ログインせず、拡張機能を切った状態で開いたページを保存し、スクリプトと、ログイン中の表示や閲覧の記録が残っていないことを確かめます（`scripts/strip-scripts.ts`、`scripts/check-pages.ts`）。ページは `tests/fixtures/` のものを先に、そのあと `eval/pages/` のものをファイル名の順に読み、同じ求人は最初に出た1件として数えます。
2. **ラベルを付ける**: 判定の結果を見ないまま、カードと詳細ページの文字だけから、求人ごとに下の「ラベルの定義」のラベルと根拠を付けます（`pnpm eval:cards` が、判定を載せないラベル付け用の一覧を作ります）。下書きは AI（Claude）が付け、判定とラベルが食い違うものと、無作為に選んだ一致などを人が確かめて直しました（`pnpm eval:review`）。
3. **3つの条件で測る**（`pnpm eval`）:

   | 条件 | 内容 |
   |---|---|
   | ① カードだけ | 記録のない状態で、カードの文字だけで判定する |
   | ② 企業単位の記録あり | 同じサイトのページをいったんすべて読み、事業内容の欄で当たった企業を記録してから判定する（使い続けた状態） |
   | ③ ふだんどおり | ②に加えて、paiza・マイナビ転職の詳細ページの結果を使う（先読みをオンにした状態） |

4. **数える**: 隠した件数、適合率（隠したもののうち対象の割合）、再現率（対象のうち隠したものの割合）、要確認にした件数、取りこぼし（対象なのに何もしなかった件数）。`unknown` のラベルは数えません。
5. **確かめる**: ルールを直し終えてから新しいページを集め、調整に使っていないデータとして1回だけ測ります（`pnpm eval:holdout`）。調整用と同じ求人は数えません。

paiza・Green・doda の3サイト（2026-10-17）:

| データ | 求人 | 対象 | ① 適合率／再現率 | ② 適合率／再現率 | ③ 適合率／再現率 |
|---|---|---|---|---|---|
| 調整用 | 287（不明8を除いて279） | 163 | 100.0%／72.4% | 100.0%／72.4% | 100.0%／86.5% |
| 確かめ用（1回目） | 89（不明3を除いて86） | 34 | 92.3%／70.6% | 92.6%／73.5% | 90.9%／88.2% |

確かめ用で誤って隠した3件（doda のカードにサイトが付けるキーワードの欄の「客先常駐」、勤務地の「プロジェクト状況」による出社の書き方、「客先常駐から脱却」の間に言葉をはさんだ書き方）は、そのあとで読み取りとルールを直しました。そのため、直したあとの確かめ用の数字は、調整に使っていないデータでの精度を表しません。

マイナビ転職（2026-10-18〜19 に追加。IT エンジニア職の検索結果）:

|---|---|---|---|---|---|
| 調整用（最初の測定） | 100 | 88 | 100.0%／72.7% | 100.0%／77.3% | 96.7%／98.9% |
| 調整用（直した後） | 100 | 88 | 100.0%／72.7% | 100.0%／77.3% | 100.0%／98.9% |

マイナビ転職ではカードに事業内容の欄がないので、①②の再現率は低く、③の先読みで大きく上がります。調整用で誤って隠した3件（応募者の経歴の「SES企業での開発経験」、「SES企業のように…ではありません」の離れた否定、「プロジェクトにより当社別拠点」の自社拠点、許可の一覧の「労働者派遣事業」）と、確かめ用で誤って隠した5件（「客先常駐原則なし」「客先常駐無＊」「客先常駐など…ありません」のような否定の形、「客先常駐・SESから…への転職」、引用のあとの「変えたい」、勤務地の「プロジェクト単位」）は、そのあとでルールを直しました。既存3サイトの数字は変わっていません。確かめ用の直したあとの数字は、調整に使っていないデータでの精度を表しません。

保存したページとラベルは、サイトの内容と企業ごとの判断を含むので公開していません。サイトのページを自動で取りに行くスクリプトも公開していません。サイトへの自動アクセスを手伝う形になるためです（`eval/lib/turns.ts` は、そのスクリプトで1件ずつ順に取りに行き、止めどきを決める部分です）。

## ラベルの定義

ラベルは求人の働き方で決めます。契約の名前は問いません。ただし、自社内の開発と社外常駐（客先常駐・SES・派遣）の両方がある企業は、その企業のどの求人も対象とします。

| ラベル | 意味 |
|---|---|
| `ses` | 自社以外の現場（客先）に常駐し、客先の指示で働く求人。どの現場で何をするかが案件しだいの求人に限らず、常駐先が1社に決まっている求人も含む。SES・準委任・請負の別は問わず、SIer やコンサルの求人も同じ基準で判断する。社外常駐のある企業の求人は、その求人の仕事が自社内でも `ses`（社外常駐の形が派遣だけなら `haken`） |
| `haken` | 派遣として働く求人（登録型、常用型・無期雇用の派遣、技術者派遣） |
| `other` | 上のどちらでもない求人（自社サービス・自社製品の開発、社内SE、自社内での受託開発など）。社外常駐のある企業の求人は含めない |
| `unknown` | 手元の情報では決めきれない。測定から外し、件数だけ報告する |

境目の扱い:

- 「客先常駐なし」と書かれていても、案件しだいで現場が変わる働き方なら `ses`。
- 企業に社外常駐があるかは、その求人の文字、企業の事業の欄、評価データにある同じ企業のほかの求人（別のサイトのものも含む）から読む。客先への訪問・打ち合わせ・出張、グループ会社への出向、応募する人の経歴として書かれた SES は含めない。
- paiza の開発内容タイプに「受託開発（社外常駐）」があれば、ほかのタイプと併記されていても、その企業には社外常駐がある。
- `ses` と `haken` はどちらも隠す対象。測るときは両方を「対象」としてまとめ、取り違えは別に数える。

ラベルは `eval/labels/<サイト>.json` に、次の形で置きます。`company` と `title` は確かめやすくするためのもので、判定には使いません。

```json
[
  {
    "jobId": "1001",
    "company": "株式会社サンプル",
    "title": "Javaエンジニア",
    "label": "ses",
    "evidence": ["Green 事業内容：SES事業", "Green 詳細の勤務地：各プロジェクト先"],
    "by": "claude",
    "note": ""
  }
]
```

`evidence` は「<サイト> <欄>：<記述>」の形で並べます。`by` は、AI の下書きなら `claude`、人が確かめて直したものは `user` にします。
